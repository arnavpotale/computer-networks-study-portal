Topologies, Delays & Multiplexing

Transmission Delay (Tt): Tt = L ÷ R (L = Frame size in bits, R = Bandwidth in bps)

Parameter 'a': a = Tp ÷ Tt = (d × R) ÷ (v × L)
Bandwidth-Delay Product: BDP = R × Tp (Maximum bits in transit along the link)

FDM Bandwidth: BWtotal = (N × Channel_BW) + ((N - 1) × Guard_Band)
TDM Frame Rate: Frame Rate = Highest input sampling rate (frames/sec)
TDM Bit Rate: Bit Rate = Frame Rate × Total bits per frame

Top 10 Exam Questions

🔥 The 10 Most Frequently Asked Exam Questions & Bullet Answers

Q1: Why is the minimum frame size of IEEE 802.3 Ethernet fixed at 64 bytes?

Under CSMA/CD, a sender must detect collisions before it finishes transmitting its frame (Tfr ≥ 2 × Tp). For a 10 Mbps Ethernet over maximum 2.5 km bus with 4 repeaters, round-trip slot time is 51.2 μs. Minimum frame bits = 10 Mbps × 51.2 μs = 512 bits = 64 bytes. If a frame is shorter, a sender could transmit the entire frame and assume successful delivery without noticing a late collision.

Q2: Why must the Fragment Offset in IPv4 be a multiple of 8 bytes?

The total IPv4 datagram size is 65,535 bytes (16-bit field), but the Fragment Offset field in the header is only 13 bits (max number 213 - 1 = 8191). To allow addressing up to 65,535 bytes using an 8191 index, offset units are multiplied by 8 (8191 × 8 = 65,528 bytes). Therefore, all intermediate fragment payloads MUST be exact multiples of 8 bytes.

Q3: Why can Go-Back-N sender window size NOT exceed 2k - 1?

If Ws = 2k, sequence numbers wrap around. If a block of 2k frames is sent and all ACKs are lost, the sender retransmits the same frames. The receiver, expecting the next batch with identical wrapped sequence numbers, cannot distinguish whether the incoming frame is a duplicate of the old frame or a brand-new frame!

Q4: What is the difference between Bit Stuffing and Byte Stuffing?

Byte Stuffing (character-oriented) inserts an ESC byte whenever the delimiter flag byte appears in data. Bit Stuffing (bit-oriented) operates on raw bits: whenever the sender detects five consecutive 1s in data, it unconditionally injects a 0 bit to prevent data from ever mimicking the flag pattern 01111110.

Q5: What is the difference between a Hub, Switch, and Router in terms of domains?

• Hub: 1 Collision Domain, 1 Broadcast Domain.
• Switch: Each port is an isolated Collision Domain (N Collision Domains), but 1 single Broadcast Domain.
• Router: Each port is an isolated Collision Domain AND an isolated Broadcast Domain (stops broadcast propagation).

Q.1 (a) [OSI vs TCP/IP Architecture] 5 Marks

"The OSI model has seven layers, whereas the TCP/IP model has only five layers.
I. Which are these two extra layers in OSI model? Explain why these two layers are not explicitly present in the TCP/IP model. [2 Marks]
II. Discuss the significance of their functions and how they are handled in modern networking. [2 Marks] + Justification [1 Mark]"

Synaptic Model Solution:
  1. Extra Layers Identified: The two extra layers in the OSI model are the Presentation Layer (Layer 6) and the Session Layer (Layer 5). 1 Mark
  2. Why Omitted from TCP/IP: The TCP/IP model was designed from a pragmatic, implementation-oriented perspective (ARPANET) rather than a rigid theoretical standard. Application developers preferred implementing session management and data formatting directly within their application software rather than relying on operating system kernel layers. 1 Mark
  3. Functions & Modern Handling of Presentation Layer:
    • Functions: Translation (e.g. ASCII to Unicode), Data Compression, and Cryptographic Encryption/Decryption.
    • Modern Handling: Handled at the Application layer via modern application protocols and libraries (e.g., TLS/HTTPS handles encryption; JSON/XML/MIME handles serialization/formatting; gzip/Brotli handles compression). 1 Mark
  4. Functions & Modern Handling of Session Layer:
    • Functions: Dialog control (simplex/half/full-duplex), session checkpointing, and synchronization tokens for crash recovery.
    • Modern Handling: Implemented directly by application-level sessions (e.g., HTTP Cookies, JWT tokens, WebSockets, or database session management). 1 Mark
  5. Synthesis: Integrating these tasks into higher layers makes the TCP/IP suite simpler, lighter, and universally adopted. 1 Mark
Q.1 (b) [Scenario-Based LAN Topology Design] 6 Marks

"A small organization needs a network to support 15 desktop computers for staff, 3 network printers, and provide secure Wi-Fi for volunteers and guests. They also need reliable, high-speed access to a cloud-based donor database. They are considering three physical topologies: Star, Bus, and Ring.
I. For each topology describe one specific advantage it would offer in this office setting. [2 Marks]
II. For each topology (Star, Bus, Ring), describe one specific disadvantage or point of failure that would be a concern. [2 Marks]
III. Based on your analysis, which topology would you recommend and why? Justify your choice. [2 Marks]"

Synaptic Model Solution:
Part I: Specific Advantages in this Office Setting [2 Marks]
  • Star Topology: Centralized management and fault isolation. If one staff PC cable is damaged or disconnected, the remaining 14 PCs and 3 network printers continue operating without interruption. High-speed switch backplane supports concurrent cloud database queries.
  • Bus Topology: Minimal cable requirements and lowest initial cabling expense. A single coaxial backbone can be routed linearly along the office desks with short drop lines.
  • Ring Topology: Predictable, deterministic token access. Every station gets equal transmission opportunity with zero packet collisions, preventing printers from starving staff PCs.
Part II: Disadvantages & Points of Failure [2 Marks]
  • Star Topology: Single point of failure at the central switch. If the central switch fails, the entire office network goes offline, severing access to printers and the cloud database. Also requires more total cable length.
  • Bus Topology: Catastrophic backbone failure and difficult troubleshooting. If the main coaxial backbone breaks or an end terminator falls off, signal reflection crashes the entire network. Troubleshooting an individual fault is extremely difficult.
  • Ring Topology: Unidirectional dependency. A failure in any single staff workstation or interface card breaks the token ring loop, bringing down the entire office unless an expensive dual-ring is used.
Part III: Recommendation & Justification [2 Marks]

Recommendation: Star Topology (using a Managed Gigabit Ethernet Switch).

Justification:

  1. The organization requires reliable access to a cloud donor database. A Star topology guarantees that individual workstation failures do not disrupt other staff.
  2. Connecting 3 network printers and a Wi-Fi Access Point requires independent port configurations (VLANs can isolate guest Wi-Fi from staff computers for security).
  3. Modern 24-port Gigabit switches are inexpensive, eliminating the cost drawback while providing 1 Gbps dedicated full-duplex links to each device.

I. Evaluation of Propagation Modes [2 Marks]:
ModeCore DiameterRefractive Index ProfileEvaluation for 2 km Campus Backbone

Q.2 (b) [Stop-and-Wait ARQ Failure Scenarios & Requirements] 5 Marks

"The figure indicates different scenarios during a frame transmission (Normal delivery, Frame 1 Lost, Frame 1 Resent, ACK 1 Lost, Frame 0 Resent).
Mention the different requirements on sender and receiver side to implement all the given scenarios correctly: [1 Mark each for 5 requirements]"

Synaptic Model Solution (The 5 Fundamental Requirements):
  1. Frame Sequence Number (Sender Requirement): Frames must be numbered with alternating 1-bit sequence numbers (0 and 1). This enables the receiver to recognize and discard duplicate frames when an ACK is lost in transit. 1 Mark
  2. Acknowledgment Number (Receiver Requirement): ACKs must carry the sequence number of the next expected frame (or the frame being acknowledged) so the sender knows precisely which frame was received successfully. 1 Mark
  3. Retransmission Timer (Sender Requirement): The sender must start a countdown timer upon transmitting a frame. If no ACK arrives before the timer expires (due to lost frame or lost ACK), the sender automatically retransmits the frame. 1 Mark
  4. Sender Buffer (Sender Requirement): The sender must retain a copy of the transmitted frame in its memory buffer until the corresponding ACK arrives, ensuring the frame can be retransmitted if needed. 1 Mark
  5. Receiver Duplicate Detection & Discard Logic (Receiver Requirement): When the receiver receives a frame with an unexpected sequence number (e.g. Frame 0 when expecting Frame 1), it must discard the duplicate data to prevent corrupted file output, but re-send the ACK so the sender can advance. 1 Mark
Q.3 (a) [Numerical: Stop-and-Wait vs Sliding Window Utilization] 4 Marks

"Assume that, in a Stop-and-Wait ARQ system, the bandwidth of the line is 1 Mbps, and 1 bit takes 20 ms to make a round trip. What is the bandwidth-delay product? If the system data frames are 2000 bits in length, what is the utilization percentage of the link? [2 Marks]
What is the utilization percentage of the link in the example given above if we have a protocol that can send up to 15 frames before stopping and worrying about the acknowledgments? [2 Marks]"

Synaptic Step-by-Step Numerical Solution:
Part 1: Bandwidth-Delay Product & Stop-and-Wait Utilization [2 Marks]
Bandwidth (R): 1 Mbps = 1 × 10⁶ bits/sec
Round Trip Time (RTT): 20 ms = 20 × 10⁻³ sec = 0.020 sec
One-way Prop Delay (T_p): RTT ÷ 2 = 10 ms = 0.010 sec
Bandwidth-Delay Product: BDP = R × RTT = (1 × 10⁶ bps) × (0.020 s) = 20,000 bits   BDP = 20,000 bits
Frame Length (L): 2000 bits
Transmission Time (T_t): T_t = L ÷ R = 2000 ÷ (1 × 10⁶) = 0.002 sec = 2 ms
Total Time for 1 Frame: T_total = T_t + RTT = 2 ms + 20 ms = 22 ms
Stop-and-Wait Utilization: η = T_t ÷ (T_t + RTT) = 2 ms ÷ 22 ms = 1 ÷ 11 ≈ 0.0909   Utilization = 9.09%
Part 2: Sliding Window Protocol Utilization (N = 15 Frames) [2 Marks]
Window Size (N): 15 frames
Total Bits Transmitted: 15 × 2000 bits = 30,000 bits
Time to send 15 frames: 15 × T_t = 15 × 2 ms = 30 ms
Formula for Utilization: η = (N × T_t) ÷ (T_t + RTT) = (15 × 2 ms) ÷ (22 ms) = 30 ÷ 22 ≈ 1.363 ⟹ Capped at 100%
Interpretation: Since 15 × T_t (30 ms) > (T_t + RTT) (22 ms), sender never waits for ACK!   Utilization = 100%

(If formula η = N × 9.09% is calculated without capping: 15 × 9.09% = 136.3%, which signifies the channel is 100% saturated with 0 idle link time.)

Q.3 (b) OR [CSMA/CD Minimum Frame Size & ALOHA Throughput] 4 Marks

"Why does an Ethernet network using the CSMA/CD protocol enforce a specific minimum frame size to ensure reliable collision detection? [2 Marks]
Suppose a station transmits frames smaller than this minimum limit. Analyze the consequences for collision detection and overall network performance. [2 Marks]
AND: Compute Pure ALOHA and Slotted ALOHA throughput for G = 1.5. [2 Marks]"

Synaptic Model Solution:
1. Why Minimum Frame Size is Enforced [2 Marks]:

In CSMA/CD, collision detection operates on a "Listen While Talk" principle. A station can detect a collision only while it is actively transmitting bits onto the cable. If a collision occurs at the farthest end of the cable (worst-case distance d), the collision noise takes one propagation delay (T_p) to occur and another T_p to travel back to the sender. Therefore, the round-trip propagation time is 2 × T_p (the contention slot). The frame transmission time (T_t = L/R) must be at least 2 × T_p:

Condition: T_fr ≥ 2 × T_p ⟹ Minimum Frame Size L_min ≥ 2 × Bandwidth × Propagation Delay
2. Consequences of Transmitting Smaller Frames [2 Marks]:
  • Undetected Collisions (Late Collision): The transmitting station completes sending its short frame and releases the channel before the collision signal arrives back. The sender assumes the frame was delivered successfully and will not trigger CSMA/CD retransmission.
  • Silent Data Loss: The receiving station receives a corrupted frame runt, fails the FCS/CRC check, and silently discards it.
  • Severe Performance Degradation: Error recovery is pushed all the way to upper transport layers (TCP timeout), causing drastic throughput collapse and latency spikes.
3. ALOHA Numerical (G = 1.5) [2 Marks]:
Pure ALOHA Formula: S = G × e^(-2G) = 1.5 × e^(-3.0) = 1.5 × 0.049787 ≈ 0.0747   S = 7.47%
Slotted ALOHA Formula: S = G × e^(-G) = 1.5 × e^(-1.5) = 1.5 × 0.22313 ≈ 0.3347   S = 33.47%
Max Comparisons: Pure ALOHA Max = 18.4% (at G=0.5) | Slotted ALOHA Max = 36.8% (at G=1.0)

If B transmits just before A's signal arrives (at time T_p - ε), a collision occurs. The collision signal takes another T_p to travel back to Station A. 🧠 1. Concept Explanation from Zero: Standalone vs. Networked

Imagine a computer sitting in an isolated room with no cables, Wi-Fi, or Bluetooth. It can run software and edit files, but it cannot share anything unless you physically walk a USB drive over. That is a standalone computer.

A computer network is formed when two or more computing devices are connected together using a transmission medium (copper cable, optical fiber, or radio waves) so they can exchange data and share hardware/software resources.

📝
Exam-Ready Definition (Tanenbaum): "A computer network is an interconnected collection of autonomous computers."
  • Interconnected: Devices are physically or wirelessly linked and capable of exchanging bits using mutually understood protocols.
  • Autonomous: Each computer operates under its own independent CPU and operating system. Neither machine can forcibly start, stop, or control the execution of the other.
  • Heterogeneous Networks: Networks are built by different vendors (Apple, Cisco, Intel, Microsoft). International open standards (IEEE, ISO, IETF) are strictly required so that heterogeneous devices can communicate.

🎯 2. Why it Matters (The Problem Solved)

The 9:00 AM Thought Experiment: If the Internet stopped working worldwide, online education, Google, hospital medical databases, and UPI banking would immediately halt. Networks solve the problem of isolated data silos by enabling:

  • Resource Sharing: Sharing expensive peripherals (high-capacity storage arrays, laser printers, GPU compute clusters).
  • Information Sharing: Instant global access to databases, web services, and enterprise workflows.
  • High Reliability via Redundancy: Replicated database servers prevent downtime if one server crashes.
  • Cost-Performance Power: A cluster of inexpensive interconnected personal computers (PCs) achieves equivalent or superior compute power compared to a monolithic mainframe at a fraction of the cost.
🔑
The 3 Core Network Evaluation Criteria:
  • Performance: Evaluated by transit time (time to travel) and response time (inquiry to response).
  • Reliability: Measured by failure frequency, link recovery speed, and disaster robustness.
  • Security: Protecting data against unauthorized intrusion and maintaining integrity.

1.3 Transmission Modes: Simplex, Half-Duplex, and Full-Duplex

The direction of signal flow between two interconnected communication devices defines the Transmission Mode:

Mode Direction of Flow Channel Capacity Usage Real-World Example Exam Summary
Simplex Unidirectional (One-way only). One station only sends; the other only receives. 100% dedicated to transmission in one direction. Keyboard to CPU, Monitor/Display, Traditional Television Broadcast. Strictly one-way. Receiver cannot acknowledge or reply.
Half-Duplex Bidirectional, but only one station at a time. Both can transmit, but not simultaneously. Entire channel capacity shared in time between transmitting and receiving. Walkie-Talkie ("Over and Out"), Push-to-talk radios. Two-way alternate. Collision occurs if both transmit at once.
Full-Duplex Simultaneous bidirectional (Both ways at the same exact time). Channel capacity divided between two directions (two separate physical links or frequency sharing). Telephone call, Modern Ethernet (Full-duplex switch links). True two-way concurrent communication without waiting.

Physical Structures

1.4 Line Configurations: Point-to-Point vs. Multipoint

How links attach to devices defines the line configuration:

Point-to-Point Configuration

  • Definition: Provides a dedicated transmission link between strictly two devices.
  • Capacity: 100% of the link capacity is reserved exclusively for transmission between those two endpoints.
  • Examples: Microwave link between two towers, direct cable between PC and router, dial-up modem to ISP.
  • Advantage: Guaranteed throughput, maximum security, zero contention.

Multipoint (Multidrop) Configuration

  • Definition: A single physical link is shared concurrently or sequentially by three or more devices.
  • Capacity: Channel capacity is shared either spatially (several devices use the link at the same time) or temporally (users take turns in time slots).
  • Examples: Traditional coaxial Bus topology (10Base2), Shared Wi-Fi radio medium.
  • Advantage: Lower cabling costs and fewer I/O ports; disadvantage: contention and collision potential.

1.5 Network Categories & What is an Internetwork?

Networks are classified by geographical scope and administrative ownership:

  • PAN (Personal Area Network): Centered around an individual person within ~10 meters (e.g., Bluetooth connecting headphones and smartwatch to phone).
  • LAN (Local Area Network): Privately owned network within a single office, building, or college campus (typically high data rate > 1 Gbps, low error rate).
  • MAN (Metropolitan Area Network): Spans an entire town or city (e.g., municipal Wi-Fi, cable television network).
  • WAN (Wide Area Network): Spans large geographic distances across states, countries, or continents (e.g., cellular backhaul, submarine cables).
  • Internetwork (An Internet): An interconnection of two or more independent, heterogeneous physical networks connected through routers and gateways. When written with a capital "I", The Internet refers to the global, publicly accessible internetwork running the TCP/IP protocol suite.

⚙️ 3. Detailed Architecture of the 6 Topologies

A. Bus Topology

All devices connect in a linear sequence to a single continuous central coaxial/copper cable called the backbone via drop lines and T-connectors.

  • 50-Ohm Terminators: Must cap both physical ends of the backbone. Why? To absorb electrical signal energy and **prevent signal reflections (echoes)** that corrupt ongoing transmissions.
  • Access Protocol: Operates half-duplex using CSMA/CD (Carrier Sense Multiple Access with Collision Detection).
  • Pros: Lowest cable requirement; inexpensive installation.
  • Cons: Single Point of Failure (backbone cable break or loose terminator collapses the entire network); difficult fault isolation; collisions increase as nodes are added.
  • Industry Use: CAN Bus (Controller Area Network) inside modern automobiles connecting ECUs for brakes, engine, and dashboard; factory sensor networks.

B. Star Topology

Every node has an independent, dedicated point-to-point cable connection to a central networking switch (or hub). All communication passes through the center.

  • Pros:
    • Fault Isolation: If one cable or PC fails, only that single PC disconnects; the other 39 or 100 computers operate normally.
    • High Scalability: Connect new PCs by plugging patch cables into unused switch ports.
    • Dedicated Performance: Switch provides dedicated full-duplex bandwidth per port (e.g., 1 Gbps), eliminating collisions.
    • Simple Troubleshooting: Switch port LEDs instantly indicate link status.
  • Cons: Central switch is a single point of failure; higher cabling length than Bus topology.
  • Industry Use: Universal standard for modern office LANs, college labs, and home Wi-Fi networks.

C. Ring Topology

Nodes are connected in a closed circular loop. Each node connects directly to its two immediate neighbors.

  • Token Passing Protocol: A special frame called a Token circulates continuously. A node transmits only when it captures the free token. This guarantees zero packet collisions and deterministic latency.
  • Cons: Unidirectional loop break halts the entire network. High latency passing through intermediate nodes.
  • Dual Ring Solution: Counter-rotating primary and secondary rings (FDDI / SONET) automatically loop back at break points to heal the network within 50 ms.
  • Industry Use: Telecom fiber optic rings (BSNL, Airtel, Jio telephone exchange backbones).

D. Mesh Topology

In a Full Mesh, every computer has a dedicated, point-to-point physical communication link directly to every other computer.

🧮

Total Physical Duplex Links: L = n(n - 1) / 2
I/O Ports Required per Node: P = n - 1
Total Ports in Network: P_total = n(n - 1)
  • Pros: Maximum fault tolerance; zero traffic contention (dedicated bandwidth); high security/privacy; zero single points of failure.
  • Cons: Quadratic cabling explosion (O(n2)); massive number of I/O ports per machine; exorbitant installation cost.
  • Industry Use: The Internet Core Backbone / Tier-1 ISPs; military defense systems.

Problem 1: Synchronous TDM Output Bit Rate

Four 1-kbps (1000 bps) channels are multiplexed using Synchronous TDM. Each slot carries 1 bit. One framing bit is added per frame.

• Frame Size (Sf): (4 channels × 1 bit) + 1 framing bit = 5 bits/frame
• Frame Rate (F): 1000 bps / 1 bit = 1,000 frames/sec
• Output Bit Rate (C): 1,000 frames/sec × 5 bits/frame = 5,000 bps (5 kbps)
• Frame Duration (Tf): 1 / 1,000 s = 1 ms (1000 μs)
Problem 2: FDM Bandwidth with Guard Bands

Five voice channels of 4 kHz each are multiplexed using FDM with 1 kHz guard bands.

• Number of Guard Bands: N - 1 = 5 - 1 = 4 guard bands
• Total Bandwidth (Btotal): (5 × 4 kHz) + (4 × 1 kHz) = 20 + 4 = 24 kHz

Switch Forwarding Modes: Cut-Through vs. Store-and-Forward

Store-and-Forward Switching

The switch receives and buffers the entire frame, verifies the 4-byte FCS/CRC checksum for bit errors. If valid, forwards to destination; if corrupt, frame is discarded immediately. Advantage: Zero error propagation. Disadvantage: Higher latency.

Cut-Through Switching

The switch reads only the first 6 bytes (Destination MAC address) and immediately starts forwarding the frame out the destination port before the rest of the frame has even arrived. Advantage: Ultra-low latency. Disadvantage: Forwards damaged/corrupted frames.

Fragment-Free Switching (Compromise)

The switch reads the first 64 bytes (minimum Ethernet frame size) to check for collision runts, then immediately begins forwarding without waiting for the full frame.

Optical Multiplexing

3.3.1 WDM (Wavelength Division Multiplexing) & CDMA Deep Dive

Wavelength Division Multiplexing (WDM) is the optical equivalent of FDM used exclusively on fiber-optic cables:

  • Operating Principle: Light beams of different wavelengths (different colors/frequencies) generated by narrow-band lasers are combined onto a single fiber using an optical multiplexer (prism or diffraction grating).
  • At the destination, an optical demultiplexer (prism) separates the individual wavelengths onto dedicated photodetector receivers.
  • CWDM (Coarse WDM): Typically supports up to 8–18 channels with wide channel spacing (20 nm).
  • DWDM (Dense WDM): Channels spaced very tightly (0.8 nm or 0.4 nm), supporting 80 to 160+ simultaneous high-speed channels over a single strand of optical fiber (terabits/sec aggregate throughput).

CDMA (Code Division Multiple Access) & Walsh Codes

In CDMA, all stations transmit at the same time over the same full frequency band. Separation is achieved through Orthogonal Chip Codes (Walsh Sequences / Chip Sequence):

Orthogonal Mathematical Rule:
Self Inner Product: C_A · C_A = m (where m is number of chips)
Cross Inner Product: C_A · C_B = 0 (strictly zero for distinct orthogonal codes)
Decoder Rule: Data_A = (Combined_Signal · C_A) ÷ m
Result Meaning: +1 means bit 1 sent   -1 means bit 0 sent   0 means station was silent

🧱 4. Deep-Dive into the 7 OSI Layers

Layer 1: Physical Layer (PDU: Bits)

Transmits raw bit streams over a physical medium. Governs mechanical/electrical specs, data rates, bit synchronization (clock sync), physical topology, and transmission modes (simplex, half-duplex, full-duplex).

Layer 2: Data Link Layer (PDU: Frames)

Layer 3: Network Layer (PDU: Packets)

Layer 4: Transport Layer (PDU: Segments)

4.2 Data Encapsulation and Decapsulation Process

When data travels through the OSI or TCP/IP protocol stack, it undergoes a systematic transformation:

Sender Side: Encapsulation (Top to Bottom)
  1. Application Layer: Generates the user message / raw data.
  2. Presentation & Session Layers: Format, compress, encrypt data, and establish dialog checkpoints.
  3. Transport Layer: Divides data into segments, adds Transport Header (H4) containing Source and Destination Port Numbers, Sequence Numbers, and Checksum. PDU = Segment.
  4. Network Layer: Encloses segment into a packet, adds Network Header (H3) containing Source and Destination IP Addresses and TTL. PDU = Packet / Datagram.
  5. Data Link Layer: Encloses packet into a frame, adds Data Link Header (H2) with MAC Addresses and a Trailer (T2) containing FCS/CRC-32 for error detection. PDU = Frame.
  6. Physical Layer: Converts frame bytes into a stream of electrical, optical, or radio pulses transmitted across the medium. PDU = Bits.
Receiver Side: Decapsulation (Bottom to Top)

The receiving host inspects, verifies, and strips each header layer-by-layer: Physical layer detects bits $ o$ Data Link verifies FCS trailer and strips MAC header $ o$ Network verifies IP and strips IP header $ o$ Transport verifies port and reassembles segments $ o$ Application receives original intact user message.

Problem: Transmission Delay vs. Propagation Delay

A host sends a 1500-byte packet over a 100 Mbps link of length 1 km (propagation speed v = 2 × 108 m/s).

• Total Link Latency: 120 μs + 5 μs = 125 μs (0.125 ms)

🧮 Topic 2: Synchronous TDM Output Bit Rate & Frame Details

📐
TDM Formulas:
Frame Size: Sf = (N × b) + Framing Bits   (where N = channels, b = bits per slot)
Frame Rate: F = Input Channel Bit Rate / b
Output Bit Rate: C = F × Sf
Frame Duration: Tf = 1 / F
Transmission Efficiency: η = (Payload Bits / Total Frame Bits) × 100%
Solved Example 1 (Basic Bit-Interleaved TDM):

Four 1-kbps (1000 bps) channels are multiplexed using Synchronous TDM. Each slot carries 1 bit. 1 framing bit is added per frame.

2. Frame Rate (F): 1000 bps / 1 bit = 1,000 frames/sec
3. Output Bit Rate (C): 1,000 frames/sec × 5 bits/frame = 5,000 bps (5 kbps)
4. Frame Duration (Tf): 1 / 1,000 s = 1 ms (1000 μs)
Solved Example 2 (Exam-Level Byte-Interleaved TDM):

Eight channels of 2400 bps each are multiplexed using character/byte interleaving (8 bits per slot). 1 byte (8 bits) of framing overhead is added per frame.

1. Frame Size (Sf): (8 channels × 8 bits) + 8 framing bits = 64 + 8 = 72 bits/frame
2. Frame Rate (F): 2400 bps / 8 bits = 300 frames/sec
3. Output Bit Rate (C): 300 frames/sec × 72 bits/frame = 21,600 bps (21.6 kbps)
4. Transmission Efficiency: (64 payload bits / 72 total bits) × 100% = 88.89%

🧮 Topic 4: Transmission Delay vs. Propagation Delay

📐
Formulas:
Transmission Delay: Ttrans = L / R   [Packet length (bits) ÷ Bandwidth (bps)]
Propagation Delay: Tprop = d / v   [Distance (m) ÷ Signal speed (v ≈ 2 × 108 m/s in copper/fiber)]
Total Latency: Ttotal = Ttrans + Tprop
Solved Example:

A 1500-byte packet is sent over a 100 Mbps link of length 1 km (signal speed v = 2 × 108 m/s).

• Given Parameters: L = 1500 × 8 = 12,000 bits, R = 100 × 106 bps, d = 1,000 m
• Transmission Delay (Ttrans): L / R = 12,000 / 108 = 120 μs (0.12 ms)
• Propagation Delay (Tprop): d / v = 1,000 / (2 × 108) = 5 μs (0.005 ms)
• Total Link Latency: 120 μs + 5 μs = 125 μs (0.125 ms)
[Practice 4.1] A 1-MB file is sent over a 10-Mbps satellite link at an altitude of 36,000 km (v = 3 × 108 m/s). Find Ttrans and Tprop. 🔥 IMPORTANT

• Bandwidth (R): 10 Mbps = 107 bps

• Propagation Delay (Tprop): d / v = (3.6 × 107) / (3 × 108) = 0.12 s (120 ms)

🧠 1. Concept Explanation from Zero: What is Data Link Layer?

The Physical Layer moves raw electrical voltages, radio pulses, or light flashes across wires, but it possesses zero intelligence. It cannot recognize where a message begins, where it ends, or whether the bits were garbled along the way. If a sender streams 10,000 continuous bits, the receiver has no way of parsing words from noise.

The Data Link Layer (Layer 2) transforms this raw, error-prone bit pipe into a structured, error-free link. It groups raw bits into manageable discrete blocks called Frames, assigns hardware-level MAC addresses for local hop-to-hop forwarding, regulates traffic speed (Flow Control) so fast senders do not swamp slow receivers, and detects corrupted transmissions (Error Control).

📝
Exam-Ready Definition: Data Link Layer Layer 2 of the OSI model responsible for node-to-node (hop-to-hop) frame delivery over a single physical link. Its primary functions are framing, physical MAC addressing, flow control, error detection/correction, and media access control.

⚙️ 2. Services Provided to the Network Layer

The Data Link Layer acts as a service provider to the Layer 3 Network Layer. In university exams, you must classify these into three distinct service classes:

Service Class Handshake? Feedback / ACK? Typical Real-World Use Case
1. Unacknowledged Connectionless No No ACK sent Ethernet LANs (low error rates); Real-time VoIP/Video where timeliness matters more than lost frames.
2. Acknowledged Connectionless No Individual ACK for each frame Wireless 802.11 (Wi-Fi) where high noise makes immediate per-frame acknowledgment necessary without setup overhead.
3. Acknowledged Connection-Oriented Yes (Setup, Transfer, Release) Guaranteed ordered delivery with ACKs High-reliability WANs, legacy X.25, and ATM networks over noisy copper trunks.

🖼️ 3. Framing Techniques: How Does the Receiver Know Frame Boundaries?

To avoid treating an endless bit stream as a single blob, the DLL divides the stream into Frames. There are four major framing techniques covered in your syllabus:

Method 1: Character Count

The frame header begins with an integer field specifying the total number of characters in the frame (including the count character itself). For example: 5 1 2 3 4 means a 5-character frame.

⚠️
Catastrophic Flaw of Character Count: If an electrical impulse corrupts a single count byte (e.g. 5 becomes 7), the receiver reads beyond the frame boundary. Framing synchronization is permanently destroyed for all subsequent frames until an idle gap occurs.

Method 2: Flag Bytes with Byte (Character) Stuffing

Frames begin and end with reserved 1-byte delimiters called FLAG bytes (typically 01111110 or ASCII DLE STX / DLE ETX).

The Accidental Collision Problem: What happens if the payload data itself contains the binary pattern of a FLAG byte? The receiver would prematurely terminate the frame!

The Solution (Byte Stuffing): Whenever a FLAG byte occurs naturally inside data, the sender inserts an Escape Byte (ESC) immediately before it. If an actual ESC occurs in data, the sender prepends another ESC (ESC ESC). The receiver strips the first ESC and delivers the original data byte to Layer 3.

Method 3: Bit Stuffing (High-Level Data Link Control - HDLC)

Allows arbitrary bit lengths (not restricted to 8-bit byte multiples). Frames start and end with the unique 8-bit flag 01111110 (six consecutive 1s surrounded by 0s).

🔑
The 5-Consecutive-Ones Rule (Must Memorize):
• Sender Rule: Whenever the sender encounters FIVE consecutive 1s (11111) in the data stream, it automatically injects a 0 bit immediately after them (producing 111110), regardless of what the next bit is.
• Receiver Rule: When the receiver sees five 1s followed by a 0, it automatically deletes the 0 bit to restore original data. If it sees five 1s followed by a 1 and 0, it recognizes the end-of-frame FLAG!
Step-by-Step Bit Stuffing Example:

Given User Data Stream: 01101111111011111010

Original Data: 0110 11111 110 11111 010
After Sender Stuffs: 0110 11111[0] 110 11111[0] 010 → 2 zero-bits stuffed
Transmitted Frame: 01111110 | 0110111110110111110010 | 01111110

Method 4: Physical Layer Coding Violations

Used in networks with redundant line encoding (such as Manchester encoding where bits must have a mid-bit transition). A high-high or low-low line state violates the coding rule and cannot represent a valid bit; hence, it is safely used as a frame boundary delimiter without wasting payload bits.

🏷️ 4. Addressing Across the Layers

  • Physical Address (MAC): 48 bits (6 bytes), hex notation (e.g. 00:1A:2B:3C:4D:5E). Burned into NIC ROM. Changes on every hop as frame travels through routers.
  • Logical Address (IP): 32 bits (IPv4), dotted-decimal (e.g. 192.168.1.1). Universal end-to-end address. Never changes across transit routers.
  • Port Address: 16 bits (0 to 65,535), identifies the specific destination process/application (e.g. Port 80 for HTTP, Port 443 for HTTPS).

📘 PPT 2: Error Detection & Error Correction

Source: Error_Detection_&_Error_Correction.pdf

⚠️ 1. Types of Transmission Errors

Data transmission across physical media is subject to thermal noise, impulse noise, and attenuation. Exam questions distinguish between:

Error Type Definition & Nature Likelihood & Cause
Single-Bit Error Only 1 solitary bit in the entire data unit is inverted (0 → 1 or 1 → 0). Extremely rare in serial transmission because noise impulse duration is usually much longer than 1 bit time.
Multiple-Bit Error Two or more non-consecutive bits in the data unit are corrupted. Occurs due to intermittent interference spikes.
Burst Error Two or more consecutive bits are corrupted from the first corrupted bit to the last corrupted bit (length of burst = last - first + 1). Most common error in real-world networks caused by lightning, motor relays, power surges, or cosmic rays whose duration spans multiple bit intervals.

🛡️ 2. Error Detection Schemes

A. Simple Parity Check (Single-Dimensional)

Appends 1 redundant parity bit to each data word such that total number of 1s is either Even (Even Parity) or Odd (Odd Parity).

⚠️
Critical Limitation: Simple parity can only detect an ODD number of bit errors (1, 3, 5). If an EVEN number of bits flip (e.g. two 0s flip to 1s), the total parity remains unchanged and the error goes completely undetected! (50% failure rate).

B. Two-Dimensional (2D) Parity Check

Data is organized into a matrix of rows and columns. A parity bit is calculated for every row AND every column.

  • Detection Capability: Detects 1, 2, and 3-bit errors. Detects most burst errors up to the width of the matrix.
  • Correction Capability: Can correct any single-bit error because the faulty bit lies precisely at the intersection of the erroneous row and erroneous column!

C. Internet Checksum

Used by Network and Transport layers (IPv4 header, TCP, UDP). Treats data as a sequence of 16-bit integers.

📐
Checksum Algorithm (Sender vs. Receiver):
• Sender: Divides data into 16-bit words. Sums all words using One's Complement Arithmetic (any carry beyond 16 bits is wrapped around and added to the lowest bit). Then inverts the result (1's complement) → This is the Checksum appended to frame.
• Receiver: Sums all received 16-bit words PLUS the received checksum using One's complement. If the sum is all 1s (0xFFFF, or inverted 0x0000), the packet is accepted as uncorrupted.

🧮 3. Cyclic Redundancy Check (CRC) & Modulo-2 Arithmetic

CRC is the industrial gold standard for Data Link error detection (used in Ethernet 802.3, Wi-Fi, SATA, USB). It operates on Modulo-2 Binary Division where addition and subtraction are identical to the bitwise XOR operation (no carries, no borrows):

0 ⊕ 0 = 0  |  1 ⊕ 1 = 0  |  0 ⊕ 1 = 1  |  1 ⊕ 0 = 1

Standard 4-Step CRC Exam Procedure:

Step 1: Identify Generator Polynomial G(x) of degree r. The divisor has (r + 1) bits.
Step 2: Append r zeros to the right of raw message bits M.
Step 3: Perform Modulo-2 division of padded message by the divisor using XOR.
Step 4: The r-bit remainder is the CRC Checksum (FCS). Transmitted codeword = Raw Message + Remainder.
Receiver Check: Receiver divides codeword by same divisor. If remainder == 0, accept!

🎯 4. Block Coding, Hamming Distance & Hamming (7,4) Code

Error detection only flags bad frames. Forward Error Correction (FEC) enables the receiver to reconstruct corrupted bits without retransmission.

📐
Fundamental Hamming Distance Laws (Crucial for 2-Mark & 4-Mark Questions):
• Hamming Distance d(x,y): Number of bit positions in which two codewords differ.
• Minimum Hamming Distance dmin: The smallest Hamming distance between any pair of valid codewords in a code scheme.
• To Detect s errors: We strictly require dmin ≥ s + 1.
• To Correct t errors: We strictly require dmin ≥ 2t + 1.

The Hamming (7,4) Code Architecture:

Encodes 4 data bits into a 7-bit codeword by adding 3 redundant parity bits (r = 3, since 2r ≥ m + r + 1 → 23 ≥ 4 + 3 + 1 = 8 holds true!).

  • Parity Bit Positions: Placed strictly at powers of 2 → Bit 1 (20), Bit 2 (21), Bit 4 (22).
  • Data Bit Positions: Remaining slots → Bit 3 (d0), Bit 5 (d1), Bit 6 (d2), Bit 7 (d3).
  • Parity Check Equations (Even Parity):
    • p1 checks bits with bit 0 set in binary (1, 3, 5, 7): p1 = b3 ⊕ b5 ⊕ b7
    • p2 checks bits with bit 1 set in binary (2, 3, 6, 7): p2 = b3 ⊕ b6 ⊕ b7
    • p4 checks bits with bit 2 set in binary (4, 5, 6, 7): p4 = b5 ⊕ b6 ⊕ b7
  • Syndrome Word (s4 s2 s1): The receiver recomputes the parities. The resulting 3-bit binary syndrome directly points to the exact 1-based index of the corrupted bit! (e.g. 1012 = 5 → Invert Bit 5 to correct!).

📘 PPT 3: Flow & Error Control Protocols (ARQ)

Source: Flow_and_Error_Control.pdf

🚦 1. Why Do We Need Flow Control?

A fast server transmitting over Gigabit fiber to a low-power mobile client with modest RAM will quickly exhaust the client's ingress buffers. Without flow control, packets overflow buffer queues and are dropped. Flow Control coordinates sender transmission rate to match receiver processing capacity.

Automatic Repeat reQuest (ARQ) combines flow control with error control (retransmissions upon timeout or damage).

⏱️ 2. Stop-and-Wait ARQ

The simplest ARQ protocol. Sender sends 1 frame, starts a retransmission timer, and freezes until positive ACK is received.

  • Sequence Numbers: Alternating 1-bit sequence numbers (0 and 1).
  • Acknowledgment (ACK): ACK contains the sequence number of the NEXT expected frame (ACK 1 confirms Frame 0).
  • Damaged Frame / Lost Frame: Timer expires → Sender retransmits frame.
  • Lost ACK: Timer expires → Sender retransmits frame. Receiver detects duplicate via sequence number, discards duplicate frame, and resends ACK.
⚠️
The Catastrophic Inefficiency of Stop-and-Wait:
Total cycle time = Ttrans + 2 × Tprop.
Utilization / Efficiency: U = 1 / (1 + 2a), where a = Tprop / Ttrans.
On satellite or high-speed long-distance links where propagation delay dwarfs transmission time (e.g. a = 100), efficiency drops below 0.5%! The sender spends 99.5% of its time idling.

🪟 3. Sliding Window Protocols: GBN vs. Selective Repeat

To overcome idle waiting, Sliding Window allows the sender to transmit multiple consecutive frames (a "window" of frames) before halting for an ACK.

Parameter Stop-and-Wait ARQ Go-Back-N (GBN) ARQ Selective Repeat (SR) ARQ
Sender Window (WS) 1 2m − 1 2m−1
Receiver Window (WR) 1 1 (no out-of-order buffer) 2m−1 (buffers out-of-order frames)
ACK Type Cumulative / Individual Cumulative (ACK n confirms all frames up to n-1) Individual / Selective (ACKs each frame + NAK)
On Corrupted Frame Timeout & Resend 1 frame Retransmits ALL N frames in window from error onwards Retransmits ONLY the 1 faulty frame
Receiver Buffering None None (discards out-of-order frames) Requires sorting buffer of size WR
Implementation Cost Very Low Moderate High (complex logic & memory)
Ideal Environment Short, noiseless links Channels with low error rate Noisy channels / High-latency satellite links
🔑
Why Must WS + WR ≤ 2m? (Famous Exam Theory Question):
If window size exceeds half the sequence number space in Selective Repeat (e.g. W = 2m), then in the event that all ACKs are lost in transit, the sender will time out and retransmit its entire window. The receiver would be unable to distinguish whether the incoming frames are duplicates of old frames or new frames from the next cycle! Restricting W ≤ 2m-1 guarantees the current receiver window never overlaps with the sender's unacknowledged sequence space.
Optimization Technique

3.5 Piggybacking: Concept, Mechanism & Timer

In two-way (full-duplex) communication, when Station A sends data to Station B, Station B must acknowledge (ACK) the frames. Transmitting separate, standalone ACK frames wastes significant bandwidth because every frame requires its own header, preamble, and framing overhead.

The Piggybacking Mechanism:

Instead of generating an immediate standalone ACK frame, the receiver delays the ACK briefly and attaches (piggybacks) the ACK sequence number into the header of an outgoing data frame destined back to Station A.

Frame Format: [ Header | Seq No | ACK No (Piggybacked) | Payload Data | FCS ]
⏱️ The Piggybacking Timer (Crucial Exam Concept): What happens if Station B has no outgoing data to send to Station A? The sender's timeout would expire! To prevent deadlocks, Station B runs an ACK Delay Timer. If Station B produces outgoing data before the timer expires, it piggybacks the ACK. If the timer expires and no data is ready, Station B immediately sends a standalone empty ACK frame.

📡 1. Medium Access Control (MAC) Protocol Taxonomy

When multiple computers share a single broadcast transmission medium (bus cable, airwaves), their signals collide and garble unless governed by a protocol. The MAC Sublayer (IEEE 802) resolves channel contention.

Category Key Protocols How Access is Decided
1. Random Access (Contention) Pure ALOHA, Slotted ALOHA, CSMA, CSMA/CD, CSMA/CA No master station; stations contend; collisions can occur and must be resolved.
2. Controlled Access Reservation, Polling (Poll/Select), Token Passing Stations consult each other or a master node; zero collisions.
3. Channelization FDMA, TDMA, CDMA Channel bandwidth is split by frequency, time, or orthogonal codes.

🏝️ 2. ALOHA Protocols: Pure vs. Slotted ALOHA

Metric Pure ALOHA (1970, Univ. of Hawaii) Slotted ALOHA (Roberts, 1972)
Transmission Rule Transmit immediately whenever a packet is ready. Continuous time. Time is divided into discrete slots equal to Tframe. Transmit strictly at slot boundary.
Vulnerable Period 2 × Tframe (Frame collides if another station sends within 1 frame time before or after). Tframe (Collisions occur only if two stations choose the exact same slot).
Throughput Formula S = G × e−2G S = G × e−G

👂 3. Carrier Sense Multiple Access (CSMA) Variants

Philosophy: "Sense before transmit" (Listen before talk).

  • 1-Persistent CSMA: Station senses medium. If busy, listens continuously. Transmits immediately when channel becomes idle (Probability = 1). Drawback: If two stations are waiting, both fire simultaneously when channel clears → Guaranteed collision!
  • Non-Persistent CSMA: If busy, backs off for a random time before re-sensing. Greatly reduces collisions, but introduces channel idle latency.
  • p-Persistent CSMA: Used in slotted channels. When idle, transmits with probability p and defers to next slot with probability (1 − p).

CSMA/CD (Carrier Sense Multiple Access with Collision Detection):

Used in Wired Ethernet (IEEE 802.3). "Listen while talking". The transmitter monitors voltage on the cable while sending. If a voltage spike exceeds the collision threshold, it halts transmission immediately, emits a 32-bit JAM signal to notify all nodes, and executes the Binary Exponential Backoff algorithm.

📐
The Minimum Frame Size Formula in CSMA/CD (High Exam Yield):
A sender MUST continue transmitting long enough to still be transmitting when a collision reflection returns from the furthest point in the network!
Ttrans ≥ 2 × Tprop  &implies  (Lmin / Bandwidth) ≥ 2 × (d / v)
Lmin = 2 × Tprop × Bandwidth
In Standard 10 Mbps Ethernet over 2.5 km bus, Lmin = 64 bytes (512 bits). Any frame smaller than 64 bytes is a collision fragment (runt frame)!

CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance):

Used in Wireless LANs (IEEE 802.11 / Wi-Fi). In wireless, radio signals attenuate quadratically, so a transmitter's own loud transmission drowns out a weak collision from a distant station ("Near-Far Problem"). Hence, wireless stations cannot detect collisions while sending; they must avoid collisions before sending.

  • Interframe Space (IFS): Delays transmission by SIFS (Shortest, high-priority ACKs), PIFS, or DIFS (Distributed IFS for data).
  • RTS / CTS Handshake: Sender transmits RTS (Request to Send); Access Point broadcasts CTS (Clear to Send) reserving the channel. This completely solves the Hidden Terminal Problem and Exposed Terminal Problem.

4.4 Token Ring (IEEE 802.5) & Fast/Gigabit Ethernet Evolution

Token Ring (IEEE 802.5)

  • Mechanism: A small special 3-byte frame called a Token circulates continuously around the ring.
  • Deterministic Access: Only the station holding the token is authorized to transmit. Zero collisions possible!
  • Token Release: After sending data and receiving it back (confirming reception by destination), the transmitting station releases the token to the next downstream station.
  • Monitor Station: One designated station acts as active monitor to re-generate lost or orphaned tokens.

Fast & Gigabit Ethernet Evolution

  • Standard Ethernet (10 Mbps): IEEE 802.3, 10Base5 (thick coax), 10Base2 (thin coax), 10Base-T (twisted pair).
  • Fast Ethernet (100 Mbps, IEEE 802.3u): 100Base-TX (Cat 5 UTP), 100Base-FX (Fiber). Preserves original 802.3 frame format; introduces Auto-Negotiation to select highest mutually supported speed.
  • Gigabit Ethernet (1000 Mbps, IEEE 802.3z / 802.3ab): 1000Base-T (Cat 5e/6 UTP). Solved the CSMA/CD distance limitation using Carrier Extension (pads frame up to 512 bytes on half-duplex) and Packet Bursting (transmits multiple frames in a single contention slot).

1. What is Bit Stuffing and why is it used? Explain the framing mechanism with an example. 🔥🔥🔥 MUST DO

Answer & Explanation:

Bit Stuffing is a bit-oriented framing method used to ensure data transparency across the physical link. Frames are delimited by a special 8-bit flag pattern: 01111110 (a zero, six consecutive ones, and a zero).

The Problem: If the user's arbitrary payload data happens to contain the exact sequence 01111110, the receiving hardware would mistakenly interpret it as an early End-of-Frame delimiter, prematurely terminating the frame and losing data.

The Bit Stuffing Rule:

  • Sender Side: Whenever the transmitter detects five consecutive '1's in the payload data, it unconditionally injects (stuffs) a '0' bit immediately after them, regardless of what the next bit is.
  • Receiver Side: Whenever the receiver detects five consecutive '1's followed by a '0', it automatically destuffs (removes) the '0' bit, restoring the original user data intact. If it sees five '1's followed by another '1', it inspects the 7th bit: a '0' indicates a genuine frame delimiter flag, while a '1' indicates an error.

Example Trace:
• Original Payload: 011111111110111110
• After Bit Stuffing: 011111011111001111100 (Three '0's inserted after every run of five 1s).

2. State the conditions for detecting s errors and correcting t errors using Hamming distance. 🔥🔥🔥 MUST DO

Answer & Explanation:

The Hamming distance between two binary words is the number of bit positions in which they differ (the weight of their XOR sum). For an error-control block code with minimum Hamming distance dmin:

1. To Detect 's' Bit Errors: dmin ≥ s + 1

Reasoning: If up to s bits are flipped, the corrupted codeword cannot reach another valid codeword. Since all valid codewords are separated by at least s + 1 bits, the error will always produce an invalid code, allowing 100% detection.

2. To Correct 't' Bit Errors: dmin ≥ 2t + 1

Reasoning: To guarantee forward error correction, the corrupted pattern must remain geometrically closer to the original valid codeword than to any other valid codeword. Non-overlapping hyperspheres of radius t require a center-to-center distance of at least 2t + 1.

3. Why does Slotted ALOHA achieve double the throughput of Pure ALOHA? Derive mathematically. 🔥🔥🔥 MUST DO

Answer & Explanation:

In Pure ALOHA, stations transmit whenever data is ready. If Station A begins sending at time t₀, any other station transmitting between (t₀ - Tfr) and (t₀ + Tfr) will collide with Station A. Thus, the Vulnerable Period is 2 × Tfr.
Assuming Poisson arrival with rate G: Throughput S = G × e-2G. Maximum throughput occurs at G = 0.5: Smax = 0.5 × e⁻¹ ≈ 18.4%.

In Slotted ALOHA, time is discretized into synchronized slots of duration Tfr. Stations can only transmit at the precise beginning of a slot boundary. Therefore, collisions can only happen if two stations generate frames in the same slot. The Vulnerable Period is reduced to 1 × Tfr.
Throughput S = G × e-G. Maximum throughput occurs at G = 1.0: Smax = 1.0 × e⁻¹ ≈ 36.8%.

Conclusion: Halving the vulnerable time doubles the channel capacity from 18.4% to 36.8%.

4. Why cannot CSMA/CD be used in Wireless Local Area Networks (Wi-Fi)? 🔥🔥🔥 MUST DO

Answer & Explanation:

CSMA/CD ("Listen While Talk") fails in wireless networks due to two physical limitations:

  1. Enormous Dynamic Power Differential: In wired copper cables, transmitted and received signal voltages are comparable. In wireless radio links, a station's transmitter radiates signals at power levels thousands of times higher (40 to 90 dB higher) than the faint incoming signal from a distant station. The station's own transmission completely deafens its receiver, making collision detection during transmission physically impossible.
  2. The Hidden Terminal Problem: Station A and Station C may both be within range of an Access Point (B), but out of radio range of each other. When A senses the channel, it detects idle airwaves and transmits; C does the same. A collision occurs at B, but neither A nor C can sense each other's transmission!

Solution: Wireless networks use CSMA/CA (Collision Avoidance) with Interframe Spaces (IFS), Contention Windows, and optional RTS/CTS (Request-to-Send / Clear-to-Send) virtual carrier sensing.

Answer & Field Breakdown:

7. Explain Cyclic Redundancy Check (CRC) encoding and decoding principles. 🔥🔥 SHOULD DO

Answer:

CRC is an error detection technique based on binary modulo-2 polynomial division (using bitwise XOR arithmetic with no carries or borrows):

  1. Sender: Given dataword of k bits and generator polynomial G(x) of degree r (r+1 bits):
    • Append r zeros to the dataword (representing dividend).
    • Divide by G(x) using modulo-2 binary division.
    • The r-bit remainder R(x) is the CRC checksum.
    • Transmitted Codeword = Dataword concatenated with R(x).
  2. Receiver: Divides received codeword by identical generator G(x). If remainder is zero, frame is error-free; non-zero indicates error.
  3. Guarantees: Detects all single-bit errors, all double errors, all odd-number errors (if x+1 is a factor of G(x)), and all burst errors of length ≤ r.
8. What is Piggybacking? Describe its mechanism, advantages, and the role of the ACK Delay Timer. 🔥🔥 SHOULD DO

Answer:

Piggybacking is the technique of attaching an acknowledgment sequence number into the header of an outgoing data frame in two-way (full-duplex) communication, rather than sending a standalone empty ACK frame.

Advantages: Eliminates separate frame overhead (preambles, headers, FCS trailers), saving significant channel bandwidth and reducing media access contention.

The ACK Delay Timer: If Station B receives data from Station A but has no immediate data to transmit back, the sender's timeout would expire. Station B starts an ACK Delay Timer: if outgoing data is ready before the timer expires, it piggybacks the ACK; if the timer expires, it immediately sends a standalone empty ACK frame to prevent retransmission timeouts.

9. Explain the Token Passing mechanism in Token Ring (IEEE 802.5). 🔥🔥 SHOULD DO

Answer:

In Token Ring, a small special 3-byte control frame called a Token circulates continuously from node to node around the ring:

  • Seizing Token: A station wanting to transmit waits until the token arrives, seizes it (changing a bit to turn it into a Start-of-Frame delimiter), and transmits its data frame.
  • Circulation & Copying: The data frame circulates around the ring. The destination station reads the address, copies the data, and sets the frame-copied bit.
  • Token Release: The frame returns to the sender, who strips it from the ring and releases a fresh token to the next downstream neighbor.
  • Key Advantage: Completely eliminates packet collisions; provides guaranteed deterministic latency.
10. How does Two-Dimensional (2D) Parity detect and correct single-bit errors? What is its limitation? 🔥🔥 SHOULD DO

Answer:

In 2D Parity, data is arranged into a two-dimensional matrix of rows and columns. A parity bit is computed for each row (horizontal parity) and an entire parity byte is calculated for all columns (vertical parity block):

  • Single-Bit Error Correction: A single flipped bit causes a parity violation in exactly one specific row and one specific column. The intersection of that row and column pinpoints the exact coordinates of the flipped bit, allowing the receiver to flip it back and achieve error correction!
  • Limitation: If 2 bits flip in the same row and 2 bits flip in the same columns (a 4-bit rectangular error), parity checks remain unchanged and the error goes completely undetected.

🧠 1. Concept Explanation from Zero: What is the Network Layer?

The Data Link Layer (Layer 2) can only deliver frames across a single physical wire or local switch (hop-to-hop). If a computer in Mumbai wants to communicate with a web server in California, the packet must traverse 15 to 25 distinct intermediate networks with completely different hardware (Wi-Fi, Ethernet, fiber optic trunks, satellite links). MAC addresses cannot route across global networks because they are flat, non-hierarchical hardware identifiers.

The Network Layer (Layer 3) provides universal Logical Addressing (IP addresses) and Routing. It inspects destination IP addresses, looks up routing tables, and selects the optimal path across thousands of interconnected networks to achieve true Host-to-Host (End-to-End) packet delivery.

📝
Exam-Ready Definition: Network Layer Layer 3 of the OSI reference model responsible for logical addressing, routing, packetizing, and end-to-end delivery of packets across multiple heterogeneous networks.

Core Functions of Layer 3:

  • Logical Addressing: Assigns globally unique 32-bit (IPv4) or 128-bit (IPv6) addresses that identify both the network and the specific host.
  • Routing: Routing algorithms (Dijkstra, Bellman-Ford, OSPF, BGP) dynamically determine the best path for packets through intermediate routers.
  • Packetizing & Encapsulation: Encapsulates Layer 4 segments into IP datagrams by attaching an IP header at sender, decapsulates at receiver.
  • Fragmentation & Reassembly: Splits large IP datagrams into smaller fragments when crossing networks with small Maximum Transmission Units (MTU).

✂️ 4. Classless Addressing (CIDR) & Subnetting

The Classful Crisis: Class A was too vast (16.7M hosts wasted per company), Class C was too tiny (254 hosts insufficient for medium businesses), and Class B ran out immediately. In 1993, Classless Inter-Domain Routing (CIDR) eliminated rigid class boundaries.

In CIDR, an IP address is accompanied by a slash notation /n (prefix length), indicating that the leftmost n bits define the Network Prefix, and the remaining (32 − n) bits define the Host ID.

Golden Subnetting Rules for /n Prefix:
• Subnet Mask: n consecutive 1s followed by (32 - n) zeros
• Total Addresses in Block: 232 − n
• Usable Host Addresses: 232 − n − 2   (subtract Network ID and Broadcast ID)
• Network Address (First): Bitwise AND between IP Address and Subnet Mask
• Broadcast Address (Last): Set all (32 - n) host bits to 1s

🔄 5. Network Address Translation (NAT)

Purpose: Solves IPv4 address exhaustion by allowing thousands of private internal computers (using 192.168.x.x or 10.x.x.x) to share a single public routable IP address to access the Internet.

  • How it Works (NAPT / PAT): When host 192.168.1.10:5000 sends a packet to Google, the NAT border router replaces the private source IP and port with its own public IP and an ephemeral port: 203.0.113.5:40001, recording the mapping in its NAT Translation Table.
  • Return Traffic: When Google replies to 203.0.113.5:40001, the NAT router looks up its table, translates destination back to 192.168.1.10:5000, and forwards internally.
Routing Mechanism

1.1.1 Journey of a Packet: Store-and-Forward Router Processing

How an intermediate router processes an incoming datagram at the Network Layer:

Step-by-Step Processing Pipeline:
  1. Physical Ingress: Router receives raw bitstream from incoming transmission link.
  2. Data Link Verification: Reassembles frame, computes CRC-32 checksum. If corrupt, discarded immediately. If valid, strips Layer 2 frame header and trailer.
  3. Network Layer Hand-off: Inspects IPv4 header. Verifies 16-bit Header Checksum.
  4. TTL Decrement: Decrements Time-to-Live (TTL) by 1. If TTL == 0, router drops packet and generates an ICMP Time Exceeded (Type 11) message to sender. Recalculates Header Checksum.
  5. Routing Table Lookup: Extracts 32-bit Destination IP. Performs Longest Prefix Match lookup to find next-hop router IP and outgoing interface.
  6. MTU & Fragmentation Check: Compares datagram Total Length against outgoing link MTU. If Total Length > MTU and DF == 1, packet is dropped with ICMP Fragmentation Needed. If DF == 0, splits into fragments.
  7. Re-encapsulation & Transmission: Resolves next-hop MAC address using ARP, encapsulates packet into a new Layer 2 frame (new source MAC, new destination MAC), and transmits out the egress port.

📦 1. IPv4 Header Architecture (20 to 60 Bytes)

An IPv4 packet is called a Datagram. It consists of a header (minimum 20 bytes, maximum 60 bytes) followed by user data (up to 65,535 bytes total length). Every network engineer must memorize all 13 fields:

Field Name Bits Detailed Function & Exam Significance
1. Version (VER) 4 bits Defines IP version. Always binary 0100 (4) for IPv4. If router does not match, packet is discarded.
2. Header Length (HLEN) 4 bits Defines header size in 4-byte words (multiplier = 4).
• Min value = 5 (5 × 4 = 20 bytes, when no options).
• Max value = 15 (15 × 4 = 60 bytes, when maximum 40B options present).
3. Service Type (TOS / DSCP) 8 bits Quality of Service (QoS). Specifies priority, delay, throughput, and reliability preferences for DiffServ packet tagging.
4. Total Length 16 bits Total length of datagram (Header + Data) in bytes. Max size = 216 − 1 = 65,535 bytes.
Data Payload Size = Total Length − (HLEN × 4).
5. Identification (ID) 16 bits Unique sequence tag assigned by sender. All fragments originating from the same datagram carry the identical ID so receiver reassembly can group them together.
6. Flags 3 bits Controls fragmentation behavior:
• Bit 0: Reserved (must be 0).
• Bit 1 (DF - Don't Fragment): 1 = Do not fragment (if packet exceeds MTU, router drops it and sends ICMP error). 0 = Fragmentation allowed.
• Bit 2 (MF - More Fragments): 1 = More fragments follow this one. 0 = This is the last fragment (or packet was never fragmented).
7. Fragmentation Offset 13 bits Specifies relative position of fragment data in the original unfragmented datagram, measured strictly in units of 8-byte blocks!
Offset Value = Byte Start Index / 8.
8. Time to Live (TTL) 8 bits Prevents packets from looping endlessly in routing loops. Decremented by at least 1 at every intermediate router. When TTL == 0, router drops packet and sends ICMP Time Exceeded message to sender.
9. Protocol 8 bits Identifies which Layer 4 transport protocol receives the payload:
• 1 = ICMP • 2 = IGMP • 6 = TCP • 17 = UDP • 89 = OSPF.
10. Header Checksum 16 bits One's complement checksum covering ONLY the header (data is checked by Layer 4 TCP/UDP). Recomputed at every router because TTL decrements!
11. Source IP Address 32 bits (4B) Original sender's 32-bit IPv4 address. Unchanged during transit (except via NAT).
12. Destination IP Address 32 bits (4B) Final destination host's 32-bit IPv4 address. Used by routers for routing table lookup.
13. Options & Padding 0 to 40 bytes Network testing, source routing, timestamping. Padded with zeros to align to 32-bit boundary.
Header Field Analysis

2.3 Type of Service (TOS) vs. Modern Differentiated Services (DiffServ)

The 8-bit field at byte offset 1 in the IPv4 header has had two historical interpretations:

Original Type of Service (RFC 791)

  • Bits 0–2 (Precedence): Priority from 000 (Routine) to 111 (Network Control).
  • Bit 3 (D - Delay): 0 = Normal, 1 = Low Delay (e.g., Telnet, SSH).
  • Bit 4 (T - Throughput): 0 = Normal, 1 = High Throughput (e.g., FTP).
  • Bit 5 (R - Reliability): 0 = Normal, 1 = High Reliability (e.g., SNMP).
  • Bit 6 (C - Cost): 0 = Normal, 1 = Minimize Monetary Cost.
  • Bit 7: Reserved (must be 0).

Modern Differentiated Services (RFC 2474)

  • Bits 0–5: DSCP (Differentiated Services Code Point) defines the Per-Hop Behavior (PHB) that routers apply to packets:
    • Expedited Forwarding (EF): Low loss, low latency, guaranteed bandwidth (VoIP).
    • Assured Forwarding (AF): 4 classes with 3 levels of drop precedence.
    • Best Effort (BE): Default standard traffic (DSCP = 000000).
  • Bits 6–7: ECN (Explicit Congestion Notification) allows routers to signal imminent congestion without dropping packets!

✂️ 1. The Maximum Transmission Unit (MTU) & Fragmentation

Every physical data link technology imposes an upper limit on the size of the frame payload it can physically carry, called the Maximum Transmission Unit (MTU):

  • Standard Ethernet: MTU = 1500 bytes
  • FDDI: MTU = 4352 bytes
  • Point-to-Point (PPP): MTU = 296 to 1500 bytes
  • X.25 / WAN links: MTU = 576 bytes

When an incoming datagram (e.g. 4000 bytes from a high-speed server) arrives at a router whose next hop has a smaller MTU (e.g. 1500 bytes), the router must slice the datagram into smaller pieces called Fragments.

📏
The Ironclad 8-Byte Offset Rule:
The Fragmentation Offset field in the IPv4 header is only 13 bits long. To map up to 65,535 bytes using only 13 bits (213 = 8192), the offset field is measured in units of 8 bytes.
Therefore, the data payload in every fragment (except possibly the very last fragment) MUST be an exact multiple of 8 bytes!

• Max Data per Fragment: MTU − Header = 1500 − 20 = 1480 bytes
• Check 8-Byte Rule: 1480 / 8 = 185 (Exactly divisible by 8! Perfect.)

1. What is the significance of the HLEN field in the IPv4 header? Calculate minimum and maximum header sizes. 🔥🔥🔥 MUST DO

Answer & Explanation:

The HLEN (Header Length) field is a 4-bit field in the IPv4 header that defines the total length of the header in units of 4-byte (32-bit) words.

  • Why a multiplier of 4 is used: A 4-bit number can only hold values from 0 to 15. Since an IPv4 header can be up to 60 bytes long, storing bytes directly would require 6 bits. Using a 4-byte multiplier allows a 4-bit field to represent lengths up to 15 × 4 = 60 bytes.
  • Minimum Header Size: When no options are used, HLEN = 0101 (decimal 5). Header size = 5 × 4 = 20 Bytes. Any packet with HLEN < 5 is invalid and discarded.
  • Maximum Header Size: When the maximum 40 bytes of options are present, HLEN = 1111 (decimal 15). Header size = 15 × 4 = 60 Bytes.
  • Data Length Calculation: Payload Data Bytes = Total Length - (HLEN × 4).
2. Why must the IPv4 Header Checksum be recalculated at every intermediate router? 🔥🔥🔥 MUST DO

Answer & Explanation:

The IPv4 Header Checksum covers only the header fields (not the payload data). It must be verified and recalculated by every single intermediate router along the transmission path because:

  1. TTL Decrement: To prevent packets from circulating endlessly in routing loops, every router decrements the Time to Live (TTL) field by at least 1. Because a field inside the header has changed, the 1's complement checksum is no longer valid.
  2. Fragmentation Updates: If the router fragments the datagram, the Flags and Fragment Offset fields are updated, requiring a fresh checksum calculation for each fragment header.
  3. Options Updates: If options like Record Route or Timestamp are active, the router appends its own IP address into the header options, modifying header bytes.
3. Why must fragment payloads in IPv4 strictly be multiples of 8 bytes? 🔥🔥🔥 MUST DO

Answer & Explanation:

The total IPv4 datagram size is defined by the 16-bit Total Length field, which can reach up to 65,535 bytes. However, the Fragment Offset field in the header is allocated only 13 bits.

A 13-bit binary integer can only represent decimal values from 0 to 8,191 (2¹³ - 1). To enable a 13-bit number to index positions across a 65,535-byte space, IP protocol designers established that each offset unit represents an 8-byte chunk (since 8,191 × 8 = 65,528 bytes, which spans the maximum datagram size).

Conclusion: Because Fragment Offset = (Starting Byte Offset ÷ 8), the payload data of every intermediate fragment (where MF = 1) MUST be an exact multiple of 8 bytes so that the starting byte offset of the subsequent fragment divides evenly by 8.

5. Explain the purpose of NAT and how Network Address Port Translation (NAPT) works. 🔥🔥🔥 MUST DO

Answer & Explanation:

Network Address Translation (NAT) conserves global public IPv4 addresses by allowing an entire private local network (hundreds of computers) to access the public Internet simultaneously using only one public IP address.

Private Address Ranges (RFC 1918):
• Class A: 10.0.0.0/8 | Class B: 172.16.0.0/12 | Class C: 192.168.0.0/16 (Non-routable on the public internet).

How NAPT (Port Multiplexing) Operates:

  1. When host 192.168.1.10:5000 sends an outgoing web request, the NAT router intercepts the packet.
  2. The router replaces the source IP with its own public IP (e.g. 203.0.113.1) and replaces the source port with a dynamically allocated external port (e.g. 61001).
  3. It records this mapping in its NAT Translation Table: [192.168.1.10:5000 ⟷ 203.0.113.1:61001].
  4. When the remote web server replies to 203.0.113.1:61001, the NAT router looks up the table, translates the destination back to 192.168.1.10:5000, and delivers the packet to the local PC.

7. Explain the function and purpose of Special IP Addresses: 0.0.0.0, 255.255.255.255, and 127.0.0.1. 🔥🔥 SHOULD DO

Answer:

  • 0.0.0.0 ("This host on this network"): Used as a temporary source IP by a client booting up (e.g. DHCP Discover) before it has been assigned a valid IP address. In routing tables, 0.0.0.0/0 denotes the Default Gateway Route.

  • 127.0.0.1 (Loopback Address): Points to the local host machine. Packets addressed to 127.x.x.x never leave the host and are immediately looped back by the network stack for internal client-server testing (e.g. running a local web server).
8. What is Subnetting? State the mathematical formulas for subnets and usable hosts. 🔥🔥 SHOULD DO

Subnetting is the process of borrowing bits from the Host ID portion of an IP address to create a Subnet ID, dividing a large network into multiple smaller, manageable, and secure logical subnets.

Number of Subnets: Subnets = 2ˢ (where s is number of borrowed subnet bits)

9. What is CIDR and Supernetting (Route Aggregation)? State the rules for combining routes. 🔥🔥 SHOULD DO

Answer:

CIDR (Classless Inter-Domain Routing) eliminates rigid class boundaries by appending a prefix length slash notation /n to the IP address.

Supernetting (Route Aggregation) is the practice of combining multiple contiguous smaller network prefixes into a single shorter prefix route to shrink Internet routing tables.

The 3 Strict Supernetting Rules:

  1. The network address blocks must be strictly contiguous without any gaps.
  2. The number of blocks combined must be an exact power of 2 (2, 4, 8, 16, etc.).
  3. The first address in the block must be evenly divisible by the total number of addresses in the aggregated block.
10. Compare the original Type of Service (TOS) field with modern Differentiated Services (DiffServ). 🔥🔥 SHOULD DO

Answer:

  • Original TOS (RFC 791): Used 8 bits: Bits 0–2 (Precedence 0–7), Bit 3 (Delay: 0=normal, 1=low), Bit 4 (Throughput: 0=normal, 1=high), Bit 5 (Reliability: 0=normal, 1=high), Bit 6 (Cost), Bit 7 (Reserved). Few routers implemented this successfully.
  • Modern DiffServ (RFC 2474): Replaced TOS with a 6-bit DSCP (Differentiated Services Code Point) and 2-bit ECN (Explicit Congestion Notification):
    • DSCP classifies traffic into Per-Hop Behaviors (PHB): Expedited Forwarding (EF) for real-time VoIP, Assured Forwarding (AF) for tiered business traffic, and Best Effort (BE) for default internet data.
    • ECN allows routers experiencing queue buildup to set bits 6–7, signaling end hosts to reduce transmission rate without dropping packets.

Step-by-Step Processing:

  2. Strip L2 Ethernet header and trailer; pass IPv4 datagram to Layer 3.

  6. Compare Total Length against egress link MTU; fragment packet if Total Length > MTU and DF = 0.
  7. Resolve next-hop MAC via ARP, encapsulate into new Layer 2 frame, compute new CRC-32 FCS, and transmit.
